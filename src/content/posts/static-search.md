静态网页把内容提前生成出来，读者打开时不必等待服务端现算页面。搜索仍然可以发生在浏览器：构建时整理文字索引，查询时再下载需要的片段。这篇原创示例稿记录一套验证思路。

## 先决定哪些文字值得被找到

菜单、页脚、订阅提示在每个页面重复出现。如果全部放进索引，搜索“文章”可能让每一页都成为结果。更有用的做法是明确指定正文边界，把标题、摘要与正文纳入，把重复导航排除。

本博客只索引文章页，而不是把首页的一段摘要当作完整文章。这样，读者能通过正文里的“倒排索引”找到这篇文章，即使这个词没有出现在文章标题中。

## 把索引放在构建之后

顺序很重要：先生成 HTML，再读取 HTML 建索引。若索引先执行，就可能拿到上一次构建的旧页面，或者面对一个空目录。

```json
{
  "scripts": {
    "build": "astro build && node scripts/index-search.mjs"
  }
}
```

流水线需要在任一步失败时停止。否则看起来部署成功，搜索却仍停留在旧内容上。索引脚本还应该检查文章数，避免没有索引到任何页面却继续上传。

### 子路径是一个真实的测试场景

部署在项目地址下时，资源位置可能是 `/astro-material-blog/pagefind/pagefind.js`。文章结果也必须指向同一个前缀。只在域名根目录测试，容易遗漏这个问题。

## 中文检索要用正文来验收

中文没有以空格分隔所有词语，搜索引擎需要做分词。测试时至少覆盖一个常见词、一个多字词组，以及不存在的关键词。不要只断言结果区域出现了某些文字，还应点击真实结果，检查目的页标题。

可以在正文写下一个独有句子，例如“紫藤书签记录了一次完整的索引验证”，然后在构建预览中搜索“紫藤书签”。这个检查能分辨全文检索和只搜索标题的实现。

## 不要忘了等待与空状态

当查询尚未结束，告诉读者正在搜索；没有匹配时，给出换词建议；网络请求失败时，提供可理解的状态。快速连续输入时，旧请求可能比新请求更晚结束，需要一个查询序号来避免旧结果覆盖新结果。

键盘体验同样属于搜索功能：快捷键打开，焦点进入输入框，Tab 留在弹窗里，Escape 关闭，焦点回到原来的按钮。完成这些，搜索才真正成为一个可用的阅读入口。
