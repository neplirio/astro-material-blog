浅色界面里的一块淡紫色，切到深色以后应该是什么？直接反转所有颜色，往往会得到刺眼的强调色和模糊的层次。这篇原创示例稿建议先为颜色命名，再考虑具体色值。

## 名字描述用途

`purple-100` 描述外观，`surface` 描述用途。页面组件更适合使用后者，因为同一个用途在不同主题下可以采用不同的颜色。

```css
:root {
  --surface: #f2edf7;
  --text: #2e2835;
  --primary: #725294;
}
:root[data-theme="dark"] {
  --surface: #231e2c;
  --text: #eee5f3;
  --primary: #d0b5ed;
}
```

正文颜色、辅助文字、边框和强调色各自承担不同职责。若组件里到处写死色值，主题切换时就容易漏掉某个角落。先收拢高频用途，再逐步整理特殊场景，不必一次建立庞大的颜色体系。

## 偏好与实际主题是两件事

用户选择“跟随系统”时，保存的是 system，而当前实际显示可能是 light 或 dark。如果只保存当前结果，系统主题变化后，页面就无法继续跟随。

可以把偏好保存到本地存储，每次加载先读偏好，再根据媒体查询计算显示结果。读取失败时仍要有合理默认值，因为浏览器可能限制存储访问。

### 在绘制之前应用

主题初始化脚本应该尽早执行。若等到页面主体加载完再设置深色，用户会先看到浅色闪烁。一个短小的内联脚本足够读取偏好并设置根元素属性，无需下载整套客户端框架。

## 深色需要重新分配层次

深色主题的卡片可以比页面背景稍亮，边框则保持克制。代码块需要独立检查：语法高亮里的一些注释颜色，在暗背景下可能难以辨认。

不要只检查正文中间的某一屏。导航、搜索弹窗、选中按钮、禁用状态和代码块都属于同一套主题。建议用一个清单走遍完整阅读路径。

## 保存之后还要再打开一次

测试主题持久化时，点击切换只是第一步。刷新页面、跳到文章页、重新打开浏览器上下文，分别验证偏好是否按预期生效。最后改动模拟的系统主题，确认只有“跟随系统”会随之改变。

好的主题切换像调节房间灯光：光线换了，物品之间的关系仍然清楚。
